# 客流观测与区间

区域人数与两两交集必须是非负整数，单位人或千人。东门、中庭、西门映射为A、B、C。时间先转UTC后形成小时桶；非整点观测向下归入所在UTC小时桶。同一观测按version选择最高版，矛盾同版隔离。

最多三个区域。两区域无交集观测时联合人数为[max(A,B),A+B]；已知交集I时为A+B-I。三区域需要全部两两交集。三方交集T下界为max(0,AB+AC-A,AB+BC-B,AC+BC-C)，上界为min(AB,AC,BC)。联合人数为A+B+C-AB-AC-BC+T。区间无可行整数时整桶隔离。输出上下界，不估算未经观测的精确人数。日汇总是分桶客次的上下界相加，不宣称是全天独立人数。

## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。运行幂等键由输入字节、参数与规则版本计算。

三方交集仅在A、B、C三个区域齐全时适用，类型triple的left必须为ABC，right必须为空。

支持区域固定为A、B、C；其他区域标识拒绝，防止三方ABC记录关联到另一组区域。

## 维护期校准裁决

探头维护后，观测可能仍停留在维护前的历史校准口径。参数 `maintenance` 声明维护窗口（`from`、`to`、可选 `regions`/`kinds`/`label`），参数 `calibrations` 声明校准账本。每条观测按下列顺序裁决：

1. 命中 `status` 为 `confirmed` 的新校准：修正后进入正式区间，计入“已采信”。
2. 仅命中 `status` 为 `carried`（或 `source` 为 `historical`/`legacy`）的历史校准：修正后进入正式区间，但在交接、对账与归档中单列为“未确认沿用”，**不计入**已采信人数。
3. 位于维护窗口内但没有任何命中校准：隔离，原因码 `CALIBRATION`，保留来源行、原值与依据。
4. 命中同编号不同内容的校准，或同一优先级内命中多条修正互相矛盾的校准：隔离，原因码 `CALIBRATION_CONFLICT`，冲突校准仍留在账本与审计中。

同编号且内容完全相同的重复校准只应用一次（审计记 `duplicate_ignored`）。已确认校准优先于历史沿用：二者同时命中且修正一致时按已确认采信；若修正不同，已确认的同样生效，视为补齐后的新口径。历史沿用只有在没有已确认校准时才作为“未确认沿用”。

校准记录字段：`id`、`basis`（页面与归档显示的校准依据）、`status`（`confirmed`/`carried`）、`factor`（默认1，必须大于0）、`offset`（默认0）、可选 `regions`（A/B/C）、`kinds`（`zone`/`pair`/`triple`，默认 `zone`）、`ids`（指定观测ID）、`bucket_from`/`bucket_to`（UTC，闭区间）。区域校准默认只修该探头自身的区域人数；要修交集或三方人数必须显式声明 `kinds`。校准作用范围由校准自身字段决定，与维护窗口相互独立：校准的时间范围留空即覆盖全部时段，维护窗口只回答“哪些观测在窗口内必须有校准依据”。

修正以**原始人数**为基数一次性计算 `raw*factor+offset`，不使用上一次修正后的人数。因此同一观测重试、重复提交同一校准、或对同一批次重跑都不会叠加修正。修正后人数必须为非负整数，否则整桶隔离。

一个时段内只要有任一观测缺少可用校准依据、校准冲突或修正后人数非法，**整个时段不进入正式区间**（`WITHHELD`）：只用剩余观测拼联合人数会系统性漏计被隔离的区域。此时仍输出该时段修正前区间，供核对漏计了多少；被隔离观测的原始行与依据全部保留。

正式区间（`business`）为全部进入区间的时段上下界之和，`certified_*` 只含没有未确认沿用的时段，`carried_*` 只含含未确认沿用的时段；`withheld_buckets` 列出整段隔离的时段。只有 `business.total` 把未确认沿用算进当天客流，交接时不得把 `business.total` 当作已采信人数。

补齐校准后重跑时，按来源内容匹配上一批次，时段签名未变的直接复用上一批模型与区间，只重算签名变化的时段（`recompute.recomputed` / `recompute.reused`）。保存批次与“最新批次”指针在同一事务内提交；保存失败返回 `SAVE`（503），上一批次及其复核版本原样保留。
